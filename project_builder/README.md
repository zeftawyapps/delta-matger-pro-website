# 🚀 نظام البناء والتهيئة المتكامل لموقع الويب (Website Tenant Builder)

مرحباً بك في نظام البناء والتهيئة الذكي الخاص بـ **Next.js Website**. تم تصميم هذا النظام ليتطابق مع نفس أسلوب تطبيق العميل (Flutter Client App) لتبسيط تهيئة الموقع وتخصيص النطاقات وروابط الـ API، ومن ثم تشغيل الموقع محلياً أو بنائه ورفعه مباشرة لاستضافة Firebase.

---

## 📋 الإعداد المبدئي (مرة واحدة فقط)
قبل تشغيل السكريبت لأول مرة، تأكد من إعطائه صلاحيات التشغيل في نظام التشغيل (macOS/Linux). افتح الـ Terminal في المجلد الرئيسي للموقع واكتب الأمر التالي:

```bash
chmod +x ./project_builder/build_client.sh
```

---

## 🌐 1. اختيار العميل النشط
الملف الرئيسي والمصدر الوحيد لتحديد العميل والبيئة النشطة لموقع الويب هو:
👉 **`project_builder/config.yaml`**

افتح هذا الملف، وقم بتعديل حقل `activeClient` ليتطابق مع العميل الذي تريد العمل عليه (على سبيل المثال: `domancy`, `local`):

```yaml
activeClient: "domancy"  # اسم العميل النشط
env: "prod"              # بيئة العمل (local, dev, prod)
```

> [!NOTE]
> * إذا لم يكن ملف تهيئة العميل موجوداً في مجلد `project_builder/clients/` محلياً، فسيقوم النظام تلقائياً بنسخه ومزامنته من مشروع الفلاتر الشقيق (`delta-mager-pro-client-app/project_builder/clients`).
> * تم إضافة ملف `.gitignore` داخل مجلد `project_builder/clients/` لحظر رفع ملفات إعدادات العملاء الحية إلى المستودع العام، مع الإبقاء على ملف `local.yaml` كمرجع للتطوير فقط.

---

## 🏃 2. تشغيل السكريبت والأوامر المتاحة

بعد تحديد العميل والبيئة في ملف الـ config، يمكنك تشغيل السكريبت من المجلد الرئيسي للمشروع بعدة طرق:

### 🖥️ أ. الوضع التفاعلي (Interactive Mode)
إذا قمت بتشغيل السكريبت دون كتابة أي معاملات إضافية، سيعرض عليك قائمة خيارات بسيطة وواضحة جداً لتختر منها بضغطة زر:
```bash
./project_builder/build_client.sh
```

**الخيارات المتاحة في القائمة:**
1. **💻 تشغيل محلي (Run Locally):** لتهيئة إعدادات العميل وتشغيل سيرفر التطوير الخاص بـ Next.js (`npm run dev`).
2. **🚀 بناء ونشر للـ Firebase (Build & Deploy):** لبناء كود الإنتاج ورفعه مباشرة للموقع المخصص للعميل على Firebase.
3. **⚙️ تهيئة الملفات فقط (Configure Only):** لتحديث ملفات التكوين والربط محلياً دون بدء عملية البناء.
4. **📦 بناء محلي فقط (Build Only):** لإنشاء نسخة إنتاجية من كود Next.js محلياً للتأكد من خلوه من الأخطاء.

---

### ⚡ ب. وضع الاختصار السريع (Direct Commands)
لتخطي القائمة التفاعلية والبدء فوراً، يمكنك كتابة الإجراء المطلوب مباشرة بجانب اسم السكريبت كمعامل:

#### 1. التشغيل المحلي الفوري (Next.js Dev Server):
```bash
./project_builder/build_client.sh run
```

#### 2. بناء الموقع إنتاجياً محلياً فقط:
```bash
./project_builder/build_client.sh build
```

#### 3. البناء والرفع المباشر للاستضافة (Firebase Deploy):
```bash
./project_builder/build_client.sh deploy
```

#### 4. التهيئة والتحديث السريع فقط دون بناء:
```bash
./project_builder/build_client.sh config
```

---

## 🧠 كيف يعمل النظام خلف الكواليس؟

1. **سكريبت البايثون (`configure.py`):**
   - يقرأ ملف العميل YAML ويستخرج منه تفاصيل الهوية وروابط الـ API حسب البيئة النشطة.
   - يقوم بتوليد ملف `src/config/clientConfig.json` بشكل ديناميكي والذي يعتمد عليه موقع الويب لقراءة إعدادات وروابط العميل.
   - يولد ملف `.firebaserc` لتوجيه العمليات للمشروع الصحيح على Firebase.
   - يولد ملف `firebase.json` لتحديد إعدادات استضافة Next.js ونطاق العميل النشط.
   - يسجل تفاصيل العملية في سجل التحديثات `version_history.md`.

2. **سكريبت الباش (`build_client.sh`):**
   - ينظم اختيارك وينفذ عمليات التشغيل المحلي أو بناء حزم Next.js والرفع باستعمال Firebase CLI.
